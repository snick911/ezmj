# EZMJ 台灣十六張麻將

以 Java Swing 製作的台灣十六張麻將。需要 JDK 17 以上才能建置。

遊戲裡的「說明」選單最上面是「簡介」：EZMJ 是什麼、網路開局的禮儀與單機版多了什麼（`HelpDialog.introPage`，網頁版說明的「簡介」寫同一件事，改了兩邊一起改）。接著「遊戲玩法」給第一次玩的人看，介紹三種玩法、怎麼開一場、牌桌畫面上哪裡是什麼、怎麼打、一局結束與存檔，以及選單（`HelpDialog.gameplayPage`）；「基本規則」與「台數計算」是規則；「關於」是著作權與授權。說明視窗不擋住牌桌，可以邊看邊打。

## 建置與打包

```
powershell -ExecutionPolicy Bypass -File build.ps1
```

腳本會編譯、執行全部測試（失敗就中止），再把成品放到 `dist\`：

| 檔案 | 說明 |
|---|---|
| `ezmj-<版號>.jar` | 可執行 jar，需要 Java 17 以上：`java -jar ezmj-<版號>.jar` |
| `EZMJ-<版號>-windows-portable.zip` | 免安裝版，解壓後執行 `EZMJ.exe`，不需要另外裝 Java |
| `EZMJ-windows-portable.zip` | 同一個免安裝版再複製一份，檔名不帶版號，每次打包都一樣，連結到最新版本時用這個 |
| `EZMJ-<版號>-setup.exe` | 安裝程式，需要 WiX 3 才會產生 |

版號只改 `src/ezmj/version.properties` 一處。

`src` 底下不是 `.java` 的檔案（版本、人像插畫與背景音樂的 MP3）會照原本的位置包進 jar。兩首 MP3 共 8.6 MB，是 jar 與免安裝版變大的主要原因，見「環境設定」的「錄好的背景音樂」。

要產生安裝程式時，把 [WiX v3.14.1](https://github.com/wixtoolset/wix3/releases/tag/wix3141rtm) 的 `wix314-binaries.zip` 解壓到 `tools\wix314\`（不進版控），或把 WiX 3 加到 PATH。

### 打包流程

每次打包前依序做：

1. 看修改內容：`git status` 與 `git diff`，連同還沒 commit 的新檔案，確認這次會包進去的東西。
2. 記下修改內容：寫進 `CHANGELOG.md`，把「未發布」改成 `## <新版號> - <日期>`，再開一個新的「未發布」。
3. 版號增加：改 `src/ezmj/version.properties`，依下面的規則決定動哪一碼。
4. 執行 `build.ps1`。

版號是 `主版.次版.修正`，看這次修改裡影響最大的一項：

| 動哪一碼 | 什麼時候 | 例子 |
|---|---|---|
| 主版（1.0.0） | 大改版，或舊的設定、榮譽榜、成就讀不回來 | 存檔格式不相容、整個換介面 |
| 次版（0.2.0） | 新功能，或改變牌局規則、計台 | 新的牌型、新的選單、新的設定 |
| 修正（0.1.1） | 只有修錯、調整文字或外觀，規則和功能都不變 | 修程式錯誤、改說明、調整排版 |

動了前面的碼，後面的碼歸零。

`CHANGELOG.md` 沒有這個版號的段落，或 `dist\` 已經有這個版號的成品時，腳本會直接停止，不會清除任何檔案。確定要用同版號重新打包，先刪除 `dist\`。

## 測試

測試不依賴框架，直接執行 `test/ezmj/AllTests.java` 的 `main` 即可。

`RefereeTest` 照「基本規則」與「台數計算」的文字另外實作一套規則，和引擎逐步比對。改規則時，說明、`Scorer`／`Round` 與這份裁判要一起改。

`OnlineTest` 測連線層，對面是測試自己開的假服務器，走真的 TCP 與 WebSocket，同一批測試兩種連線各跑一次。協定改了要和 `ezmjService` 的 README 一起看。

## 程式結構

| 套件 | 職責 |
|---|---|
| `ezmj.model` | 牌、牌牆、骰子、面子、玩家、設定 |
| `ezmj.rules` | 胡牌判定、計台 |
| `ezmj.engine` | 單局流程、整場牌局與結算（不依賴 Swing） |
| `ezmj.bot` | 電腦玩家：四個等級的思考邏輯 |
| `ezmj.table` | 一桌牌的行牌流程：輪到誰、等誰決定、倒數與代打（不依賴 Swing，可有多位真人） |
| `ezmj.online` | 連線對戰的客戶端：TCP 與 WebSocket 連線、登入、ping 與重連，把服務器的訊息翻成局面（不依賴 Swing，不算規則） |
| `ezmj.career` | 修業模式：檔案的籌碼與存讀、挑戰關卡與任務判定、修練的出題與判對錯、段位證照、每套紀錄放在哪個資料夾（不依賴 Swing） |
| `ezmj.report` | 把畫好的頁面圖寫成 PDF（不依賴 Swing） |
| `ezmj.ui` | Swing 畫面，把牌桌流程演出來 |

牌桌畫面只讀 `engine.RoundView` 與 `engine.GameView`，不管局面從哪裡來：單機是 `Round` 與 `GameSession`，連線是 `online.OnlineGame`。動畫、音效與按鈕都在 `ui.TablePresenter`，局面來源與決定的去處由它的 `Table` 介面決定：單機是 `GameController`，連線是 `OnlineController`。畫面上的座位 0 一定是自己，連線時服務器的座位在 `OnlineGame` 就轉好了。

## 開始畫面

開始畫面有三個按鈕：

| 按鈕 | 說明 |
|---|---|
| 修業模式 | 建立自己的檔案，籌碼一路帶著打，還有挑戰關卡與記牌、看聽的修練。見下一節 |
| 練習牌局 | 以前的單機對電腦：每場自己選姓名、籌碼本金、底、每台與電腦等級，有存檔時可以繼續上次的練習牌局 |
| 連線對戰 | 進大廳，見「連線對戰」 |

練習牌局的成就、統計、榮譽榜與存檔照舊放在 `.ezmj` 底下，以前的紀錄都還在。

**畫面上的文字**：開始畫面、練習牌局、修業模式、修業檔案與連線對戰的畫面只寫一句開場白（例如修業模式的「這是你自己的麻將修練……在麻將江湖中混出一番名堂」）或必要的資訊（帳上籌碼、救濟金補到多少、房號），怎麼玩、規則與專家模式有哪些不一樣，都寫在「說明」→「遊戲玩法」與「基本規則」。專家模式的勾選框只寫「開啟」，滑鼠停著也只提示去哪裡看說明。修業模式「建立新檔案」的視窗和牌桌一樣是深綠底金字（`ui.CreateCareerDialog`），只有名字、起始籌碼與專家模式三列，沒填名字或名字有不雅字眼時直接在欄位下面提示。

**名字與不雅字眼**：練習牌局、修業檔案、連線對戰的名字、房間名稱與聊天都不能有不雅字眼，字詞與比對規則在 `model.BadWords`，網頁版直接編譯同一份，要加減字詞改那裡。中文跳過空白與標點比對，英文看全形、大小寫與 f*ck、f u c k 這類寫法；常用詞剛好有的字（幹嘛、樹幹、三小時、我操心）列在 `ALLOWED` 不算。練習牌局與連線對戰的按鈕不因為名字沒填、房號不完整或底台太大變灰（正在連線時例外），按下去才用 `StartPanel.nameAccepted` 這類檢查跳出提醒；修業模式「建立新檔案」照它的設計在欄位下面提示。聊天有不雅字眼就不送出，收到別人的聊天由 `OnlineGame.parseChat` 把不雅字眼換成＊，舊版的程式沒有擋。`ezmjService` 0.9.0 起服務器也用同一份擋，改過的程式也送不出去。

## 修業模式

最多三個檔案，存在使用者目錄的 `.ezmj\career\1` 到 `3`。每個資料夾裡有 `profile.properties`（名字、起始籌碼、帳上籌碼、最高籌碼、破產次數、過關紀錄、打到一半的是哪一場），以及這個檔案自己的 `achievements.properties`、`stats.properties`、`honor.properties`、`certificate.properties` 與 `save.properties`，上傳過個人圖像的話還有 `avatar.png`。檔案之間、檔案和練習牌局之間的紀錄都不相干。這些 `.properties` 都是封存的，改了就讀不出來，見「存檔加密與擴充」。刪除檔案只刪這幾個檔，資料夾裡有別的東西就留著。

- **建立檔案**：名字最多 8 字，起始籌碼選 1000、20000 或 100000（預設 20000），建立之後不能改。以前用別的起始籌碼建立的檔案照樣能用。也可以勾「專家模式」，見下面。
- **專家模式**：建立檔案時勾選，之後不能改（`profile.properties` 的 `expert`，以前的檔案沒有就是一般模式）。起始籌碼固定 100（`EXPERT_STARTING_CHIPS`），底與每台不照 1/10、1/20，只要不大於帳上的籌碼就能選，所以 100 能選底 50、100，每台 10 到 100；檔案畫面先選最小的 50／10。牌局照專家模式打（見「專家模式」），一般對戰與挑戰都是，每次等待固定 10 秒（`EXPERT_WAIT_SECONDS`），牌局中選單的「等待時間」不能改。救濟金照同一個道理：連最小的底 50 都付不起才能領，補回 100，不比新開一個專家檔案多。挑戰獎金是原本的 1/20（`EXPERT_REWARD_SHARE`、`CareerProfile.rewardFor`）：第一關 100、出師 2500，全部 7350，修練另外 310；關卡的獎金都要除得盡 20，測試會檢查。
- **一般對戰**：打四圈，選底、每台與三家電腦等級。帶帳上的籌碼上桌，三家電腦也帶一樣多；每局結算完就照桌上的籌碼改帳，輸贏不會重來。帶上桌最多一億，其餘留在帳上，四家加起來才放得進 `int`。修業模式不能用電腦代打，一般對戰與挑戰都沒有這顆按鈕。
- **底台照籌碼開放**：籌碼越多能選的底台越大，底最多帳上的 1/10、每台最多 1/20，檔案畫面只列選得了的。例如帳上 10 萬，底最多 1 萬、每台最多 5000；底最大 200000、每台最大 100000，要帳上 200 萬才都選得到。選項是底 50、100、300、500、1000、2000、5000、10000、20000、50000、100000、200000，每台 10、20、50、100、200、500、1000、2000、5000、10000、20000、50000、100000，和練習牌局不一樣，中間多了幾格才不會一下跳太多。開打時 `CareerProfile.startGeneral` 也會再檢查一次。
- **稱號**：帳上的籌碼曾經到過下面的數目就得到稱號，輸掉也不會拿走（看的是最高籌碼，稱號不另外存檔）。檔案畫面與檔案列表顯示目前的稱號與下一個要多少；牌局中拿到的，牌局結束視窗會說。

  | 帳上到過 | 稱號 |
  |---|---|
  | 200000 | 牌桌新貴 |
  | 1000000 | 百萬雀士 |
  | 5000000 | 麻將大亨 |
  | 20000000 | 富甲一方 |
  | 100000000 | 億萬雀神 |
- **離開與存檔**：離開或關閉時可以存檔，之後在檔案畫面按「繼續牌局」。選「結束這場」的話，一般對戰已經打完的局照算，打到一半的那局不算；挑戰算失敗。檔案上記著打到一半的牌局，存檔卻讀不回來時，也照這樣當作結束。有沒打完的牌局時不能開新的。
- **救濟金**：帳上不到 500（連最小的底 50 都選不了）、又沒有打到一半的牌局，可以領救濟金補到 1000，記一次破產。1000 是最小的起始籌碼，救濟金不會比新開一個檔案還多。這時候也可以打挑戰賺獎金。
- **帳是怎麼記的**：一般對戰開打時記下沒帶上桌的部分，每局結算完帳上就是「留在帳上的 ＋ 桌上的籌碼」，同一局重複結算也不會多算。

每局結算完判定一次任務：成功或失敗一確定，這場就在那一局結束，不一定打滿圈數；規定的圈數打完或有人輸光，還沒成功就是失敗。牌桌右側平均思考那一行下面有任務框，寫著關卡、任務、加星條件與進度。挑戰不能用電腦代打。

**星等**：每關最多三顆星（`Challenge.MAX_STARS`）。第一顆是過關，另外兩顆是每關自己的加星條件，在過關那一刻判定（`Challenge.check` 的 `stars`，位元 0 是過關、1 與 2 是兩個加星條件）。因為過關時這場就結束了，加星條件都要是當下就能判定的，例如「到那時沒有放槍」「自摸過關」「東風圈內過關」（看最後打完的那局是第幾圈，`ChallengeFacts.lastCircle`）、「籌碼第一名」「籌碼 30000 以上」「胡一手 8 台以上」「胡出門清一摸三」。檔案記每關拿過哪幾顆（`profile.properties` 的 `stars.<關卡>=1,3`），幾次挑戰拿到的合起來算，以前的檔案過了的關算一顆。第一次拿到第二或第三顆星，各給過關獎金的 1/5（`STAR_BONUS_SHARE`、`CareerProfile.starBonus`），專家檔案照專家獎金算；第一次過關就拿到的也照給。新增關卡要給兩個不重複的加星條件，測試會檢查。

挑戰的每一局照算這個檔案的成就，但整場類的成就、「打完幾場」與榮譽榜只算一般對戰，因為挑戰的圈數和規則不一樣，提早結束時籌碼最多也不代表什麼。挑戰的局也不記進統計（所以也不影響段位證照）：對手、籌碼與圈數都是關卡定好的，混進統計會讓胡牌率、放槍率不準。以前的版本挑戰的局有記進統計，已經記的分不出來，照舊留著。

要新增關卡，只要在 `Challenge` 裡加一項；任務的寫法在同一個檔案，看得到的局面在 `ChallengeFacts`。

### 修練關卡

挑戰列表最後一章是「修練」，練記牌與看聽。修練不是完整的牌局：不記統計、成就、榮譽榜與段位，不留打到一半的存檔，中途離開就是沒過關。修練自成一條線（`Challenge.line(true)`、`Challenge.isDrill`），記牌一一開始就開放，過了前一關才開下一關，和十二關完整牌局互不影響：`Challenge.previous` 只在同一條線上找。畫面上叫「修練 1」到「修練 6」（`Challenge.label`），檔案畫面的標題分開寫「已過 a / 12　修練 b / 6」。宣告順序是記牌、看聽交錯，設定在 `career.Drill`。

| 修練 5 | 記牌三 | 三家職業・第 5～7 輪停・問 5 題 | 10 秒 | 答對 4 題 | 6 秒 | 1500 |
| 修練 6 | 看聽三 | 聽 3～6 種、多為一色牌・看牌 8 秒・5 手 | 10 秒 | 對 4 手 | 5 秒 | 1500 |

- **記牌**（`career.MemoryQuiz`）：照專家模式打一局，棄牌每家只看得到最後一張，自己的牌自己打。一輪是四家各打一張，開打時隨機決定第幾輪停（`MainFrame.startDrill`），打出那麼多張就停下來，作答視窗蓋住牌桌開始問；還沒到就有人胡牌或流局，就用已經打出的牌問。題目有四種：最後打出的幾張（依序點）、某家最後兩張（依序點）、某張牌一共被打出幾張（0～4 張）、某張牌是誰打的（只問剛好一家打過的牌）。各家照這局的門風叫，例如「東家（名字，你）」。打牌事件由 `GameController.watchEvents` 交給 `MainFrame.drillEvent` 記下來。專家模式最多等 10 秒的規定一樣適用，修業的專家檔案固定 10 秒。
- **看聽**（`career.WaitsQuiz`）：亮一手聽牌的 16 張，看牌時間到或按「看好了」就蓋起來，從 34 種牌點出全部聽的牌按「確定」，少選、多選都算錯。牌是五組面子加一對眼再拿掉一張，聽牌照 `HandAnalyzer.waits` 算，種數在範圍內才出；看聽三有四分之三是一色牌。
- **作答**（`ui.DrillDialog`，34 種牌是 `ui.TilePicker`，一排牌是 `ui.TileRow`）：每題從可以作答時開始計時，逾時算錯、秒數照限時算。答完立刻說對錯與正解，答錯的也列出自己答的，2.2 秒後自動下一題，最後一頁寫成績、星與獎金。
- **星等與獎金**：三顆星是過關、全部答對、平均作答秒數不超過上表（`Drill.stars`）。獎金照挑戰關卡的規則：第一次過關給獎金，第一次拿到第二、三顆星各給 1/5；專家檔案是 1/20，記牌、看聽各 30、50、75。獎金比完整牌局的關卡少，因為不是完整的牌局。

## 連線對戰

開始畫面按「連線對戰」進大廳，輸入名字，就可以從列表挑一間公開的房間加入、用六碼房號加入，或開一間新房間。規則全部在服務器上跑，客戶端只送決定。

服務器固定是部署在 Render 的 [EZMJ Server](https://github.com/snick911/ezmjService)（`wss://ezmj-server.onrender.com/ws`），畫面上不能改，也不會從設定檔讀。免費主機閒置後會睡著，第一個連線可能要等一分鐘。

測試時用系統屬性換服務器，不要碰到線上的：`-Dezmj.server=<位址>`。位址有兩種寫法：`host` 或 `host:port` 走 TCP，預設 port 7788；`ws://` 或 `wss://` 開頭的網址走 WebSocket。`OnlineTrial` 會自己帶上這個屬性。打包好的 `EZMJ.exe` 沒辦法直接帶參數，要測的話設環境變數 `JAVA_TOOL_OPTIONS=-Dezmj.server=<位址>`。

- **大廳**：列出等人中、還有空位的公開房間，有房間名稱、房主、人數、籌碼／底／台、每次等待秒數，以及「隨時補位」與「專家」兩欄（有開就打勾），新開的在前面，最多 50 間。開了隨時補位、正在打、還有電腦可以換的牌局也列出來，名稱旁標綠色的「牌局中」，排在等人的房間後面（`listRooms` 帶 `supports: ["substitute"]`，服務器 0.10.0 起才列）。選一間按「加入」或連點兩下就加入。只有大廳顯示在畫面上時每 5 秒更新一次（大廳外面包了捲軸，所以看 `HierarchyEvent.SHOWING_CHANGED`，不看 `componentShown`），也可以按「重新整理」。列表走一條不登入的連線，服務器不會主動推送；舊服務器不認得列表時只顯示一句說明，用房號加入和開房間照樣能用。
- **開房間**：選房間名稱（最多 30 字，空白就用「<名字>的房間」）、要不要設成私人房間、隨時補位、籌碼本金、底、每台、補位電腦的等級、每次等待秒數（5 到 300，多人桌不能不限時）、電腦速度與要不要用專家模式。私人房間不列在大廳，只能用房號加入。專家模式是房間的設定，房間裡每個人都照專家模式打（見「專家模式」）。房間畫面顯示房間名稱與房號，私人房間標著「私人」、專家模式的房間標著「專家模式」、隨時補位的標著「隨時補位」，把房號告訴朋友就好；畫面也會列出玩家與連線狀態。
- **隨時補位**：開了的房間開打之後，電腦在打的座位別人也能中途加入替換，流程在服務器 README 的「隨時補位」。加入牌局中的房間先問一次；服務器保留座位後送 `substituteWaiting`，這時還在大廳，下方寫在等哪一家，按「取消」就關掉連線（服務器發現斷線就讓出座位）。上場時才收到 `room`，和重連一樣接上牌桌；整場先打完的話收到 `lobby` 的 `room`，坐進房間。收到 `substituted` 時牌桌上方跳公告（`TableCanvas.announce`，停 8 秒）、那一家旁邊跳「補位」、紀錄與聊天區各留一行。訊息的讀法與畫面上的字在 `online.Substitution`，和網頁版一樣。中途補位的不列入榮譽榜（服務器記的）。
- **開局**：只有房主可以，不到四人由電腦補滿。打完整場回到房間，可以再開一場。
- **結果視窗**：大家都看完就開下一局，沒看完時最多等服務器的時間（流局 5 秒，其他 15 秒）。
- **電腦代打**：多人遊戲不能用，牌桌上沒有這顆按鈕，服務器也會拒絕。斷線或離開的座位才由電腦接手。

等待時間與速度看房間的設定，環境設定裡的兩項只影響單機。平均思考時間只有單機才有，連線牌局那一行顯示房號。

**斷線重連**：連線斷了會自己重連，最多試 3 分鐘，這段時間座位由電腦代打，別人會看到名字旁標著「（斷線）」。接回來時局面、還在等你決定的詢問都會補上。程式被關掉的話，重開之後按「連線對戰」的「接回牌局」。還沒開局時斷線就等於離開房間，牌局中按「離開牌局」也回不來了。

**存檔**：連線牌局不寫入本機的牌局存檔、統計、成就與榮譽榜。輸贏歷程只記這次開著程式時看到的局。使用者目錄的 `.ezmj\online.properties` 記著上次的名字；牌局中還有 token 與房號，牌局結束就清掉。token 等於這個座位的身分，不要給別人。

連線都走 `wss://`，有加密。測試時用的 `host:port` 與 `ws://` 是明碼，只適合本機或信任的網路。

要實際跑一遍，先編好 `ezmjService`，再用下面的指令開一台服務器和好幾個視窗，自己按按鈕打牌，驗證開房、從大廳加入、私人房間不列在大廳、用房號加入、打完整場、斷線重連、殺掉程式後接回，以及從大廳補位進牌局中的房間。截圖與紀錄都在輸出資料夾，不會碰到真正的設定與存檔，服務器的榮譽榜檔也寫在那裡。第三個參數給 `substitute` 就只跑補位那一項：

```
java -cp build\classes;build\test-classes ezmj.ui.OnlineTrial <服務器的 classpath> <輸出資料夾> [substitute]
```

## 環境設定

選單「環境設定」的選擇會存到使用者目錄的 `.ezmj\settings.properties`，刪除這個檔案就回到預設值。

| 設定 | 預設 | 說明 |
|---|---|---|
| 字體大小 | 100% | 85% 到 150%，立刻套用，視窗比預設大時再乘上解析度放大的比例。牌面上的字不跟著變 |
| 麻將大小 | 100% | 100% 到 150%，立刻套用。視窗寬度不夠時手牌會稍微重疊，最多疊到牌寬的約兩成，再大就要把視窗放大才看得出差別 |
| 等待時間 | -1 | 真人每次可以考慮的秒數，-1 表示不限時。時間到還沒決定：吃、碰、槓、胡視為放棄，輪到出牌則打出最右邊的手牌（也就是放棄自摸與槓） |
| 遊戲速度 | 中 | 慢、中、快，電腦出牌前與等宣告時停多久，改了下一個動作就生效 |
| 解析度 | 1360 × 900 | 視窗大小或最大化。放不進螢幕的選項不能選。視窗比 1360 × 900 大時，字、按鈕、選單與清單等比例放大（`Resolution.zoomFor`）：寬高取比較小的比例、以 5% 為一級往下取，放大後還放得進視窗，例如 1920 × 1080 是 120%，螢幕只有 1080 高時是 115%；1600 × 900 和預設一樣高，不放大。換解析度、拖拉視窗邊框（停手 0.2 秒後）或最大化都會照新的大小重排；比預設小時不縮小。牌桌畫布本來就跟著視窗縮放，上面的字只跟字體大小（`Theme.canvasFont`），不會放大兩次。開始畫面、練習牌局、修業模式與連線對戰的畫面外面包了捲軸（`ui.FitScroll`）：放得下時和以前一樣撐滿視窗，視窗太小或字體太大、連畫面的最小大小都放不下時才出現捲軸，按鈕不會被切掉。目前 1280 × 720、1366 × 768 的視窗開到字體 125% 時練習牌局、150% 時練習牌局與修業檔案會出現捲軸 |
| 背景音樂 | 茶館閒情 | 六首曲子或關閉，都循環播放，音量照「音量」的背景音樂。前四首是原創曲子，樂譜在 `MusicScores`，由 `BackgroundMusic` 即時合成，不需要音樂檔；選單隔一條線之後是兩首錄好的曲子「清空牌桌（Clear the Board）」與「木板暖陽（Sunlight on the Floorboards）」，見下面的「錄好的背景音樂」 |
| 音量 | 音樂 50、音效 100、語音 100 | 分別調整，0 到 100，拉動時立刻生效。司儀跟著語音的音量 |
| 音效 | 開 | 打牌、吃碰槓、胡牌與流局的聲音，由 `SoundEffects` 合成，沒有音效裝置時不出聲 |
| 語音 | 開 | 喊打出的牌，以及吃、碰、槓、胡、自摸、聽牌；司儀宣布流局與連莊，見下面的「司儀」。關掉時喊牌與司儀都不出聲。聲音有兩種：女聲 Hanhan 與男聲 Zhiwei，電腦角色隨機男女，各用男聲或女聲。條子有人喊「X條」、有人喊「X索」，畫面上一律寫「X條」：電腦角色照名字決定（`BambooCall.forName`），同一個人每次都一樣，大約一半一半；自己一律喊條。喊「X條」的那幾句不加快、音量最多加 20%，音高照風格調，女聲的「條」加快又加大聲會糊成像「支」。第一次用 Windows 內建的中文語音產生，存在 `.ezmj\voice\<風格>`，刪除後會重新產生；缺任何一句、或說法與風格改過（資料夾裡 `signature.txt` 的指紋對不上），就整個風格重做，這段時間不出聲。沒有中文語音或不是 Windows 時選項會停用 |
| 我的語音 | 女聲 | 自己喊牌用女聲或男聲，選了會喊一聲「碰」試聽，牌局中改也立刻生效。自己的條子一律喊「X條」，不能設定；以前存的喊索設定讀進來就不管了 |
| 語音風格 | 熱血 | 輕快、抑揚或熱血，見下面。選了會用自己的聲音喊一聲「碰」試聽；第一次選的風格要先在背景產生，幾秒後才響 |
| 動畫 | 開 | 擲骰子、發牌、牌的飛行與大字，只影響畫面，不影響牌局結果。關閉時立刻開局，胡牌後也立刻跳出結果 |

**語音風格**：Windows 內建的中文語音（女聲 Hanhan、男聲 Zhiwei）念起來很平，所以產生語音時用 SSML 調整（`model.VoiceStyle`）。每句話的每個字有自己的高低（0 到 9，寫在 `VoiceLines.Line` 與牌的喊法裡），重點字拉高，例如「自摸」的摸、「三萬」的萬：

| 風格 | 整句提高 | 每一級再提高 | 語速 | 音量 | 句尾 |
|---|---|---|---|---|---|
| 輕快 | 15% | 0 | 加快 20% | 加大 30% | |
| 抑揚 | 10% | 6% | 加快 15% | 加大 30% | |
| 熱血（預設） | 25% | 10% | 加快 25% | 加大 40% | 驚嘆號 |

每種風格的語音檔存在自己的資料夾（`hype`、`lively`、`brisk`），換回已經產生過的風格不用重做。以前放在 `.ezmj\voice` 底下的舊語音檔用不到，開啟時刪掉。

以前「自摸」會另外把聲音拉高、一路上揚、推到接近滿格，聽起來太尖，已經拿掉；各句的起伏都交給語音風格。

**一句念完才念下一句**：新的一句不打斷還沒念完的那句，排在後面等它念完，例如打出的牌還沒喊完就有人碰，「碰」會等牌名喊完才喊。排著的牌名只要又有新的一句進來就不念了，語音才不會越落越後面；吃、碰、槓、胡、自摸、聽牌與司儀的話一定會念到。熱血風格一張牌喊起來約 0.4 秒，所以「碰」最多晚這麼久。

**司儀**：和玩家、電腦角色喊牌的聲音分開，不跟著語音風格。流局時宣布「流局」（以前用喊牌的女聲，現在改由司儀）；連莊的局開始時說「連莊，連X拉X」，X 是這局的連莊數（`round.streak()`），例如連二是「連莊，連二拉二」，和中央「連莊」的大字同時，沒有動畫時也說，連線對戰不演大字但司儀照樣說。連一到連二十各有一句，連莊超過二十次只說「連莊」。語音關掉時不說，音量跟著語音。和喊牌排同一個隊，一句念完才念下一句。

司儀要穩重清楚，所以 SSML 只放慢 5%，不調音高、不加大聲、句尾不加驚嘆號（`VoiceLines.announcerSsml`），產生後每句調到一樣大聲（最大振幅滿格的 90%），內建語音念「流局」本來只有「連莊」那句的一半大。聲音挑 Windows 新版語音介面（OneCore）的女聲，依序找 Yating、Hanhan、任何台灣女聲、任何中文女聲；新版介面不能用時改用舊介面（SAPI）的中文女聲。存在 `.ezmj\voice\announcer`，和喊牌一樣有 `signature.txt`，說法或挑聲音的順序改了就整個重做。

挑聲音時比較過這台開發機上所有的中文女聲，同一句「連莊，連二拉二」量出來：

| 聲音 | 介面 | 長度 | 平均音高 | 結果 |
|---|---|---|---|---|
| Microsoft Yating | OneCore | 1.48 秒 | 187 Hz | 選用：比較低沉、念得較慢較穩，最像司儀；「流局」也比較清楚大聲 |
| Microsoft Hanhan | OneCore | 1.23 秒 | 206 Hz | 音調偏高、念得快，聽起來比較年輕，留給喊牌 |
| Microsoft Hanhan Desktop | SAPI | 1.24 秒 | 205 Hz | 和 OneCore 的 Hanhan 是同一個聲音，只是升頻到 44.1 kHz |

這幾個都是 16 kHz 的聲音，音質一樣。HsiaoChen、HsiaoYu 這類 neural 語音是 Azure 與 Edge「大聲朗讀」的線上語音，要連網、要金鑰或走非公開的介面，不能離線放進遊戲；Windows 11 朗讀程式的「自然語音」只給朗讀程式用，程式叫不到，Windows 10 也沒有。

**錄好的背景音樂**：「清空牌桌」與「木板暖陽」是作者提供的 MP3（192 kbps、約 3 分鐘，各 4.3 MB），放在 `src/ezmj/ui/music`，打包時跟著程式走。Java Sound 解不了 MP3，所以第一次播放時由 `RecordedMusic` 用 Windows 內建的 Media Foundation（`MediaTranscoder`，透過 PowerShell）轉成 44.1 kHz、16 位元、立體聲的 WAV，存在 `.ezmj\music`，一首約 1.3 秒、31 MB；旁邊的 `.signature` 記著 MP3 的 SHA-256，曲子換了就重新轉，刪掉資料夾也會重新轉。這兩首混音得比合成的曲子大聲，播放前把 RMS 壓到 -17 dBFS（合成的四首在 -14.5 到 -19.9 dBFS 之間），同一個音量聽起來才差不多。播放時整首放進記憶體（約 31 MB）用 `Clip` 循環，曲尾約 2 秒的安靜之後從頭再來。不是 Windows 或轉不了檔（例如沒有 Media Feature Pack 的 Windows N 版）時，這兩首不出聲，其他曲子照常。

當初也考慮過另外兩種做法：開發時就轉成 WAV 放進程式，jar 與免安裝版的 zip 會多出 63 MB（目前 zip 約 30 MB），壓成 22 kHz 單聲道也要 16 MB，而且音質變差；或加一個純 Java 的 MP3 解碼器（例如 LGPL 授權的 JLayer），跨平台、也不用轉檔，但要把第三方的程式碼放進專案與 jpackage，這次沒有用。現在的做法讓 jar 與 zip 只多 8.6 MB 的 MP3。

| 設定 | 選項 |
|---|---|
| 籌碼本金 | 10000、20000、50000、100000、500000、1000000、5000000、10000000 |
| 底 | 50、100、300、500、1000、5000、10000、50000、100000、500000、1000000 |
| 每台 | 10、20、50、100、200、5000、10000、50000、100000、200000、500000、1000000 |

底和每台都不能大於籌碼本金，等於可以。不符合時開始練習牌局與開房間的按鈕會停用，並顯示「底和每台不能大於籌碼本金」；修業模式的一般對戰看帶上桌的籌碼。`GameConfig` 也照這條規則檢查，讀到不符合的存檔就當作讀不出來；連線時服務器也會檢查。

金額都用 `int`，最大的選項也放得下：每一筆付款是底 ＋ 台數 × 每台，籌碼本金一千萬、底與每台一百萬時，自摸三家付要到一家 700 多台才會超過，牌型台數加起來不到 100 台，剩下的要靠連莊超過 300 次。統計的累計輸贏會一直加上去，所以是 `long`。

## 結果與牌局結束

胡牌時牌桌中間跳出大字，分成三種：

| 種類 | 樣子 | 時間 |
|---|---|---|
| 胡別家打出的牌 | 金字深底框，三個金色的圈接連往外擴散 | 1.1 秒 |
| 自摸 | 金字深底框，後面一團變大的金光與 16 道慢慢轉的金紅光芒 | 1.4 秒 |
| 大胡（牌型台數 10 台以上，胡或自摸都算） | 紅色漸層框，字下面多寫台數，字放大後會跳動；一開始紅金閃一下，24 道金白光芒，彩片往外噴再落下 | 2.4 秒 |

台數是結果視窗的「牌型合計」，不算莊家台。流局只有灰字，1.1 秒。

大字跳出的同時，贏家的手牌從左到右一張一張推倒：每張隔 0.035 秒開始，先抬起壓扁、再翻成牌面落回原位，0.24 秒翻完；別家原本是牌背，自己的本來就是牌面，看起來是整排往前倒。胡的那張最後翻，有金框，外面一圈金光擴散 0.65 秒。沒有動畫時，一局結束後胡的那張照樣有金框。

大字演到 4/5 時開始結算：金色籌碼從付錢的人飛向贏家（每家付錢的人 5 顆，一顆隔 0.06 秒，每顆飛 0.45 秒，走一道往上的弧線），付錢的人位置跳出紅色「−400」，第一顆落地時贏家跳出金色「+1200」並彈一下，數字慢慢往上飄，最後淡掉，整段 1.2 秒。計分表的籌碼先顯示結算前的數目，第一顆落地時在 0.55 秒內滾到結算後的數目；籌碼落地時有喀喀聲。流局沒有輸贏就不演籌碼。

結果視窗等這些演完才跳出來（`TableCanvas.endAnimationMs`），連線時倒數會扣掉這段時間。「動畫」關閉時都不演，立刻跳出結果。

每局結果視窗會倒數，時間到自動進入下一局：流局 10 秒，其他 60 秒，也可以直接按按鈕。視窗也列出其他家的手牌，放槍的人會標出來。

四圈打完或有人籌碼輸到 0 以下，牌局就結束。結束視窗顯示結束原因、總局數與流局數，以及四家的名次、胡牌、自摸、放槍、輸贏與籌碼。

牌局結束視窗還有兩顆按鈕，單機與連線都有，畫法和網頁版一樣（`ui.GameReport`）：

- 「分享結果圖」：把最終排名畫成一張直的圖（1080 × 1350），先預覽。「複製圖片」放進剪貼簿，到 LINE、Messenger 的對話框按 Ctrl+V 貼上；「存成圖片…」存成 PNG。圖上寫結束原因、底台、局數、結束時間與房間名稱（單機沒有），不寫房號，私人房的房號傳出去別人就能加入。
- 「存成輸贏 PDF…」：A4 橫放，第一頁是底台與最終排名，接著是每一局的圈風、莊家、結果、牌型與台數、四家輸贏與自己的累計，最後一列是合計，一頁放不下就接到下一頁。頁面先畫成圖再放進 PDF（`report.PdfWriter`），中文不用內嵌字型，但字不能選取。存好可以直接開啟。

存檔的對話框第一次開在桌面，之後記得上次選的資料夾，直到程式關掉；檔名是結束時間，例如 `ezmj-結果-20261109-2130.png`、`ezmj-輸贏歷程-20261109-2130.pdf`。

牌桌右側的「輸贏歷程」列出這場每一局的圈風、莊家、結果、牌型台數、四家輸贏與自己的累計，滑鼠停在結果上可以看牌型。開著也能繼續打，牌局結束視窗也能查看。歷程不存檔，離開牌局就清除。

牌桌中間與右側上方顯示圈風和局風，例如「東風南局」。局風依起莊算：莊家是起莊那位時是東局，下莊一次就往下一局，連莊時不變，四局打完換圈又回到東局。右側那行後面再接連莊次數，例如「東風南局 連1」。連線時舊服務器沒有送局風，就照以前顯示「東風圈」。

牌桌右側的表格列出四家的門風、玩家與籌碼，莊家在門風後面標著紅色圓圈框住的紅字「莊」，連莊時圓圈右邊再寫紅色粗體的連莊次數（連 2 就寫 2），滑鼠停著會寫「莊家，連N拉N」。牌桌上名字旁邊的「莊」照舊。

牌桌右側也會顯示自己的平均思考時間：從摸牌或可以吃碰槓胡開始，到打出牌、胡或決定過為止。吃碰槓之後要打出牌才算一次。電腦代打與報聽之後不計入，被別人更大的宣告搶先、還沒決定的那次也不算。

牌桌右側的「紀錄」一律預設收起來，只顯示最新一則，按右邊的箭頭或點那一行展開；箭頭朝下是展開、朝上是收合，滑鼠停著有說明。連線的牌桌下面空出來的地方是聊天，跟電腦打的一人房間也有，只是沒有人回：訊息列表、輸入框與「送出」，按 Enter 也送出。一則最多 100 字，服務器每人每 10 秒最多收 5 則，太快或內容不合會在聊天區下方顯示原因；舊服務器不認得聊天時顯示「這台服務器還不能聊天。」。聊天不保留歷史，斷線期間的訊息不補送，在房間畫面等人時收到的也不顯示。單機沒有服務器，沒有聊天。

## 擲骰子與牌牆

牌桌中央方框四邊名字的外面是牌牆：每家面前 18 墩、每墩上下兩張，共 144 張，四面像風車一樣各佔一個角。拿走的墩空出來，只剩下面那張的墩比較暗。棄牌排在牌牆外面，每張 30 × 40（牌桌單位），8 張一排；一排的一半寬要小於棄牌到中心的距離（123），相鄰兩家在角落才不會疊在一起，所以 8 張一排時這已經是最大。麻將放大到留不下三排棄牌時，中央最多縮到 90%，棄牌才不會壓到自己的手牌。

每局開始時莊家擲三顆骰子，照台灣的習慣開門。單機牌局連莊時，擲骰子前先在中央跳出「連莊」的大字，下面白字寫「連 N 拉 N」，外面和胡牌一樣有金圈擴散，演 1.5 秒（`TableCanvas.STREAK_BANNER_MS`）才擲骰子，這段時間手牌還沒發，動作列的提示寫「連莊：連N拉N」，司儀同時說「連莊，連N拉N」（見「環境設定」的「司儀」）；連線對戰的服務器只留 3 秒給骰子和發牌，大字暫時不演，司儀照樣說。整局中央方框在「剩餘 N 張」下面也用紅色粗體寫著「連N拉N」，單機與連線都有。


1. 三顆骰子從莊家面前邊轉邊跳到中央，0.65 秒停下來，下面亮出總點數，1 點與 4 點是紅色的。
2. 從莊家起照行牌順序數點數，莊家是 1，數到的那家開門；再從那家牌牆的右端數點數那麼多墩，牌牆上這裡有一條金線。
3. 1.1 秒後開始發牌：從開門處往順時針拿，每家每批四張輪流拿，最後是莊家的第 17 張，牌從牌牆上那一墩飛過去。中央的字等骰子淡出才出現。

之後一般摸牌從牌頭拿；補花與開槓後補的牌從開門處的另一邊，也就是牌尾拿。最後 16 張留著不摸，和以前一樣。紀錄會寫一行「莊家 擲出 4、5、2，共 11 點，從某某的牌牆開門」。「動畫」關閉時不演骰子與發牌，紀錄照寫，牌牆照畫。

骰子只決定從哪裡開門，不影響拿到什麼牌：牌牆是洗好的，從哪裡開門機率都一樣，所以引擎的 `Wall` 照舊只記牌頭與牌尾，畫面上的位置由 `engine.WallRing` 算，從局面看得到的剩餘張數、花牌與槓推回牌頭與牌尾各拿了幾張。

- **單機**：每局另外擲，不動牌局的亂數，同一個種子打出來的牌一樣。骰子不存檔，接回存檔時重新擲，開門的位置可能和存檔前不同。
- **連線**：服務器沒有送骰子，用房號、莊家的服務器座位、圈風、局風與連莊數算（`OnlineGame.dice`），同桌的人不管坐哪裡、用 Swing 還是網頁、斷線接回，看到的都一樣。同一間房間再開一場時，第一局可能和上一場一樣。服務器在 `roundStart` 之後留 3 秒（`dealMs`）才行牌，骰子加發牌約 2.4 秒，在這之內。

## 牌局存檔

練習牌局存在使用者目錄的 `.ezmj\save.properties`，只有一份。刪除這個檔案就沒有可以繼續的練習牌局。修業檔案各有一份，在自己的資料夾，見「修業模式」。

- 關閉視窗或按「離開牌局」時可以選存檔、不存檔或取消。不存檔會刪掉存檔。修業模式是「結束這場」，見「修業模式」。
- 每次輪到真人決定、每局結算完都會自動存，程式當掉時可以接回上一次輪到真人的時候。
- 練習牌局的畫面有存檔時會多一個「繼續上次的練習牌局」。開新局會蓋掉存檔，開之前會先問。牌局打完就刪掉存檔。
- 接回來時牌牆順序、手牌與整場的輸贏歷程都和原本一樣，有沒有用過電腦代打也會記得；電腦代打的開關回到關閉。之後新開的局用種子與局數換一組亂數，所以一樣是隨機的。
- 讀不懂、被改過或牌的張數不對的存檔不會接回，當作沒有存檔，原因記在 `.ezmj\error.log`。存檔是封存的，見「存檔加密與擴充」。

強制結束程式的話，可以從上一次輪到真人的時候重打。這是單機遊戲，沒有特別防這件事。

## 存檔加密與擴充

玩家的存檔與紀錄都是封存的：練習牌局與每個修業檔案的 `save`、`achievements`、`stats`、`honor`、`certificate`，以及修業檔案的 `profile`（段位證照的個人圖像 `avatar.png` 不封存）。用記事本打開是看不懂的位元組，改了任何一個位元組都讀不出來。被改過或壞掉的紀錄當作空的，存檔當作沒有，修業檔案只能刪除，原因記在 `.ezmj\error.log`。`settings.properties` 與 `online.properties` 照舊是文字檔，刪除或手動改都可以。

- **怎麼封存**：`model.SealedStore`。Properties 的內容用 AES-GCM 加密並驗證，檔名也算在驗證裡，所以統計檔改名成存檔也讀不出來。檔案開頭是 `EZMJSEAL` 與封存的版本，後面是 nonce 與密文。只算檔名，整個 `.ezmj` 搬到別台電腦還是讀得出來。
- **擋得住什麼**：金鑰寫在程式裡，擋的是用記事本改籌碼、過關與成就。看得懂原始碼的人還是做得出讀得進去的檔案，把整個檔案換回以前的備份也擋不住；要真的防，紀錄得放在服務器上。
- **存什麼與怎麼存分開**：各類別只管內容，`load`／`save` 多一個 `model.PropertyStore` 參數決定怎麼存。`PropertyStore.PLAIN` 是文字檔，`SealedStore.INSTANCE` 是封存的。遊戲本身一律經過 `career.Records.STORE`（`Records` 與 `CareerSlot`）。只有 `Path` 的舊方法還是文字檔，留給測試與 `ezmjService`：服務器的榮譽榜經過 `HonorRoll.load(Path)`／`save(Path)` 轉成文字存到 GitHub，不能封存。
- **舊的存檔**：0.9.1 以前是文字檔。新版第一次開啟時（`Records.openHome`）把 `.ezmj` 與三格修業檔案裡的明碼存檔原地封存，內容不變，然後留下 `.ezmj\sealed.properties` 當記號。有記號之後就不再收明碼的檔案。刪掉這個記號的話，下次開啟會再轉一次，所以它也算在「擋不住看得懂的人」裡。舊版程式讀不懂封存的檔案，裝回舊版的話紀錄會不見。

新增東西時照下面的規則，舊的存檔就讀得出來：

- **新增項目**：讀的時候給預設值，舊檔沒有這一項就用預設值。看不懂的項目一律略過，所以檔案裡多了東西也不會壞。
- **名稱不要改**：成就（`Achievement`、`Achievement.Counter`）、挑戰關卡（`Challenge`）、電腦等級與個性都是用 enum 的名稱存的。可以新增、可以調順序，改名的話舊檔裡的就認不得了。關卡可以插在中間：已經過的關一直開放，後面過過的關不會被鎖。
- **格式版本**：每個檔案都寫 `format`（牌局存檔是 `version`），沒寫的是第 1 版。同一個項目的意思變了才加一，讀的地方照檔案的版本換算舊的值。牌局存檔比程式新的不接回，免得用看不懂的牌局繼續打。
- **封存版本**：要換加密方式時，把 `SealedStore.VERSION` 加一，`read` 照檔案開頭的版本選解法，舊的照樣讀得出來，寫一律用最新的。

## 錯誤記錄

沒有被處理的錯誤都記在使用者目錄的 `.ezmj\error.log`，連同時間、執行緒、這場的亂數種子與局面。一次執行最多記 20 筆，檔案超過 512 KB 就換成 `error.log.old` 重新開始。

畫面執行緒出錯時牌局的流程會斷掉，所以會跳出說明並回到練習牌局或修業檔案的畫面，牌局可以從存檔接著打。音效、語音這些背景執行緒的錯誤只記錄，不打斷牌局。

## 統計

選單「統計」列出真人玩家的累計成績：局數、胡牌率、自摸率、放槍率、胡牌平均台數與最高台數、累計輸贏、打完的場數、第一名與平均名次，也能依同桌的電腦等級分開看。同桌有兩種等級時兩邊都算，所以各等級的局數加起來會超過總計。

每局結算完就存到使用者目錄的 `.ezmj\stats.properties`，刪除這個檔案就清空；修業檔案的存在自己的資料夾。計算方式和成就一樣：開了電腦代打之後，這場剩下的局與整場都不列入，在那之前自己打完的局仍然算數。修業模式的挑戰關卡與修練不列入統計，只算一般對戰。

統計另外依三家電腦裡最弱的是哪一級各記一份（`weakest.<等級>`，`PlayerStats.weakestAtLeast`），每局只加一份，段位證照用它算「三家都是某等級以上」的局。這份是有段位證照之後才開始記的，以前的局只在總計與同桌等級裡；畫面上的統計沒有列出來。

| 八段 | 三家都是職業 | 2000 | 27% | 4.9% | ≤ 15.5% |
| 九段 | 三家都是職業 | 4000 | 30% | 5.1% | ≤ 14.5% |

門檻參考 `Tournament` 的電腦互打：實力相當時每家胡牌率約 22 到 24%、自摸率 5 到 7%、放槍率 15 到 20%；職業對三家職業是胡 23.6%、自摸 6.6%、放槍 16.9%，職業在混桌是胡 28.2%、放槍 15.2%，初學者在混桌只有胡 15.4%、自摸 3.7%，放槍 21.9%。自摸看運氣的成分大，門檻壓低，七段到九段每段只多 0.2%（測試檢查 0.1% 到 0.3%）。八段、九段要長期穩定贏過三家職業一大截，九段的 4000 局大約要打 180 場以上。比率用千分之幾比，剛好等於門檻就算，放槍率剛好等於上限也算。門檻改過之前已經拿到的段位不會收回（只升不降）。

- **什麼時候升段**：每局記進統計之後判定，該局的結果視窗寫「晉升 N 段」，牌局結束視窗再說一次。打開證照或「說明 → 段位證照」時也會照目前的成績判定，以前就打夠的人一打開就拿得到。同時到了好幾段就直接給最高的，所以只跟職業打的人可能直接是七段。
- **只升不降**：之後成績掉下來也不收回。證書上的局數、胡牌數、自摸數、胡牌率、自摸率、放槍率是升段那天、那一段看的那些局（例如七段寫的是三家都是職業的局），認定日期也是那天。放槍數是後來才記進證照的，以前發的證照放槍率寫「—」。
- **證書**：1600 × 1131 的圖（A4 橫放的比例），米色紙、紅框金線，有名字、段位、認定日期、成績、16 碼證號、證書編號（由段位、日期與成績算出，例如 `EZMJ-7-20261109-59F0`）、個人圖像與「雀藝認證」的印。字要在縮小的預覽和 LINE 的縮圖裡也看得清楚：名字 86、說明 38、成績六格的小標題 34（深紅粗體）與數字 46、日期與證號 34 以上。可以「複製圖片」貼到 LINE，或「存成圖片…」。
- **證照視窗**：左邊是證書，右邊是名字、證號與下一段的進度，按鈕排在最下面。證書預覽照螢幕可以放視窗的範圍（扣掉工作列）放到最大，最寬 1000（跟著字體大小），放不下就縮，最窄 360；點證書會放大到整個螢幕放得下的大小。右邊的說明照固定寬度折行，字體放大時視窗不會被一行長字撐寬。1280×720 到 2560×1440 的螢幕、字體 85% 到 150% 都檢查過放得進螢幕。
- **名字**：不能改。修業檔案一律是建立檔案時取的名字；練習牌局是第一次記進統計那一局的名字，之後換名字打也不變。最多 8 字。
- **證號**：16 碼英數混合，規則在 `career.CertificateNumber`：`EZ`、段位 1–9、認定年份的個位數、月份 A–M（跳過 I）、兩碼日、六碼亂數，最後三碼是驗證碼。亂數與驗證碼只用 2–9 與不含 I、O 的大寫字母，不會把 0 和 O、1 和 I 看錯。驗證碼是前 13 碼、證書上的名字與一段固定的鹽做 FNV-1a 雜湊再攪過，換成三個字；名字或證號錯一個字就對不上。前 13 碼升段時產生、存在證照裡，之後不變；以前沒有證號的證照照段位、日期與成績補一個，每次都一樣。證照視窗的「驗證證號…」輸入證號與名字，對得上就說是哪一段、哪一天認定的（年份照個位數推回不晚於今年的那一年）。算法在程式裡，擋的是隨手改字，擋不住看得懂原始碼的人。
- **個人圖像**：預設圖庫有十張：名字的第一個字、兩張人像插畫「自摸佳人」「型男雀士」，以及一條、一筒、紅中、發財、東風、梅、竹。插畫是作者提供的圖，裁成 512 × 512 的 JPEG 放在 `src/ezmj/ui/avatars`，打包時跟著程式走；其他由程式畫，不需要圖檔。也可以上傳 PNG、JPG、GIF 或 BMP，從中間裁成 512 × 512 的正方形，存成那套紀錄資料夾裡的 `avatar.png`（不封存，改了也只是換一張圖）。上傳的圖不見了或讀不出來，就用第一張預設圖。
- **存檔**：`certificate.properties`，和其他紀錄一樣封存。記著名字、圖像、段位、日期、當時的成績與證號的前 13 碼（`serial`）；認不得的段位當作還沒入段。段位用 `Dan` 的名稱存，不要改名；證號的鹽也不要改，改了以前的證號都驗不過。
- 開了電腦代打之後的局不算，挑戰關卡的局不算，連線對戰也不算，和統計一樣。

## 成就

選單「成就」列出全部成就與達成日期，分成牌型、大牌、連續、累計、整場五類，還沒達成的累計成就會顯示進度。達成時會顯示在該局的結果視窗或牌局結束視窗。

成就都是看真人玩家的表現，每局結束就存到使用者目錄的 `.ezmj\achievements.properties`，重開遊戲後都還在，刪除這個檔案就清空；修業檔案的存在自己的資料夾，挑戰關卡不判定整場類的成就。成就與累計次數每局記錄：開了電腦代打之後，這場剩下的局與整場類成就都不列入，在那之前自己打完的局仍然算數。中途離開的牌局也一樣，已經打完的局數算數，只是不會判定整場類的成就。

要新增成就，只要在 `Achievement` 裡加一項。

## 榮譽榜

選單「榮譽榜」記錄真人玩家的成績，胡牌數、自摸數、贏錢金額、放槍數各自留下最高的十筆，存在使用者目錄的 `.ezmj\honor.properties`，刪除這個檔案就清空；修業檔案的存在自己的資料夾，只記一般對戰，挑戰關卡不列入。

牌局打到結束（四圈打完或有人輸光）才記錄，最後一局的結果視窗出現之前就會存檔，重開遊戲後紀錄還在。中途離開或用過電腦代打都不算。數值是 0 以下的類別不列入，數值相同時先達成的排前面。

贏錢金額照底與每台分榜（`HonorRoll.Stakes`），每組底台各留十筆，不同底台的輸贏不放在同一個榜上比；結束時說的名次也是同底台的。榜的上面有選單換底台，打開時先看最近有新紀錄的那組（同一天的看底台大的）。最多留 `HonorRoll.MAX_STAKES`（20）組底台，超過時拿掉這場以外最久沒有新紀錄的那組，檔案與服務器的訊息才不會一直變大。

存檔是第 2 版（`format=2`）：分底台的榜存成 `WINNINGS.底x台.名次.欄位`，另外照舊存一份不分底台的 `WINNINGS.名次.欄位`，舊版讀得懂、服務器也拿來回給舊的網頁版。讀到第 1 版的檔案時，每筆紀錄本來就記著底與每台，所以把各類別留下的紀錄（同一場只算一次）照底台排進各自的贏錢榜。`ezmjService` 用同一份 `HonorRoll`，存檔格式一樣。

## 八仙過海與七搶一

八張花牌都亮出來時立即胡，不看手牌，開局補花時也一樣，由程式自動宣告。

- **八仙過海**：一家集滿八張。算自摸，三家付錢。
- **七搶一**：一家七張、別家一張。七張的人拿走那張花，算那家放槍，只有他付錢。

兩種都是 8 台，不另計其他牌型，莊家台照一般規則加。

## 吃碰槓選牌

只有一種選擇時，按下吃、碰、槓就直接宣告；胡與自摸也是按了就胡。吃有多種組合、或自己回合有多張牌能槓時才進入選牌：能用的手牌維持原色，不能選的蓋上遮罩，點手牌就決定。吃牌時點共用的牌後再選一張。「取消」回到上一步，倒數不會重新計時。

亮出來的牌組排在手牌左邊，四家都是各自的左手邊。

**宣告的先後**：已經決定的宣告比每一位還在考慮的人能做的選項都大，就不再等他們，直接成立。大小只看種類：胡 > 槓、碰 > 吃，同樣是胡就照舊等。電腦、代打與報聽的人自動做的宣告，要等宣告開始 2 秒（`TableFlow.BOT_CLAIM_MS`）才算數，所以你只能吃、電腦要碰時，2 秒後電腦就先碰走，不用等你按。真人對真人也一樣。被搶先的人按鈕收起來，提示會寫「阿土 碰走了 三萬」。

**吃碰之後要打牌**：吃、碰、槓之後輪到自己打牌時，動作列的提示放大成金色粗體並一閃一閃（每 0.45 秒換一次金色與白色），自己的手牌外框也亮起金色圓角框，一明一暗，週期 1 秒，直到打出牌。

## 報聽與電腦代打

**聽牌**（程式裡叫報聽，畫面上一律寫「聽牌」）：單機牌局在打牌之前聽牌。輪到自己時，只要打出某張牌就會聽牌（`Round.readyDiscards`），動作列就多一個半透明的「聽牌」按鈕（平常 50% 不透明，滑鼠移上去才不透明）。按下後進入選牌：打出去會聽牌的牌加上金框，其他手牌蓋上遮罩不能點，提示列出「打哪張聽哪些牌」（超過 4 種打法只說幾種，一種打法聽超過 3 種牌只說幾種）；點一張金框的牌就打出並進入聽牌模式（`TableFlow.declareListening(seat, waitId, tile)`），「取消」回到一般打牌。沒按聽牌就直接打出去的，打完不再問。

專家模式與連線對戰照以前的做法：照常打牌，打出之後剩下的手牌已經聽牌、還沒報聽，動作列就多一個「聽牌」按鈕。機會一直到這位玩家下一次摸牌、吃碰槓或這局結束，放棄別家打出的牌不影響。專家模式聽牌之後，動作列的提示只寫「【聽牌中】」，不列出等哪些牌。

報聽之後進入原本的聽牌模式：手牌鎖定，自動摸打、自動胡，不再吃碰槓。和以前不同的是報聽是公開的：全桌都看得到，那位玩家中央方框那一邊的名字右端有紅底金框的圓形「聽」，報聽時跳出「聽牌」的大字，「聽」從 2.4 倍大彈回原本大小，外面兩個金圈擴散，共 0.9 秒。胡牌時多算「聽牌」1 台，自摸或胡別家的牌都算，也算在牌型合計裡，所以會影響 10 台以上的大胡。

電腦也會報聽：初學者不報；一般只看聽幾種，聽兩種以上才報（愛衝與愛做大牌一聽就報、保守的單騎不報）；業餘數全桌扣完後還剩幾張能胡；職業另外考慮報了就不能換聽、不能防守，別家也會防著打，底大台小或別家看起來已經聽牌時要更多張才報。職業與業餘看得到別家公開的報聽，報聽的人一定算聽牌，估台數也多 1 台。

存檔會記下誰報聽了、誰還有報聽的機會。以前的存檔只記自己聽牌模式等的牌，讀回來當作自己報聽了。

**電腦代打**：練習牌局牌桌右側的開關，隨時可以開關，由職業等級的電腦替玩家決定。修業模式（一般對戰與挑戰）與多人遊戲都沒有這個開關。電腦一樣只拿得到 `TableView`，只看得到該座位合法的資訊。

## 專家模式

練習牌局的開始畫面、修業模式建立檔案時可以勾選（`GameConfig.expert`，存檔的 `config.expert`；以前的存檔沒有就是一般模式）。連線對戰開房間時也可以勾，房間裡每個人都照專家模式打，大廳與房間畫面會標出來，也能加入網頁版開的專家模式房間。專家模式的牌桌：

- **聽牌**：打牌前沒有半透明的聽牌按鈕，打出之後已經聽牌才出現「聽牌」按鈕（見「報聽與電腦代打」）；聽牌之後提示只寫「【聽牌中】」。
- **紀錄**：右側的紀錄一直收著，只顯示最新一則，展開的箭頭藏起來。
- **牌河**：每家只畫最後打出的那一張，畫在牌河的第一格，看不出打了幾張；被吃、碰、槓或胡走了就不畫（牌桌記下每家剛打出時牌河有幾張，張數變了就是被拿走）。打出牌的飛行動畫也飛到第一格。
- **剩餘張數**：中央方框不寫「剩餘 N 張」，只有圈風局風，連莊時下面照樣有紅字「連N拉N」。

修業模式的專家檔案另外有起始籌碼、底台、等待時間與救濟金的規定，見「修業模式」。

**連線對戰的專家模式**是房間的設定，存在服務器上（`createRoom` 與 `room`、`rooms` 的 `options.expert`，`RoomSettings.expert`）：

- 牌桌照 `room` 訊息的 `options.expert` 決定（`OnlineController.isExpert`），斷線重連或「接回牌局」時服務器會再送一次，照樣是專家模式。舊服務器沒有這一欄，就是一般模式；開房間時勾了但服務器不認得，房間也是一般模式，畫面照服務器說的。
- 服務器（ezmjService 0.7.0 起）在專家模式的房間不給打哪張會聽牌（`askTurn` 的 `readyDiscards` 是空的），也不接受舊的 `listen`，聽牌照樣是打完牌才問（`canListen`）。
- 加入房間時帶 `"supports": ["expert", "substitute"]`，`expert` 說明這個客戶端會照專家模式藏資訊（`substitute` 見連線對戰的「隨時補位」）；服務器 0.7.0 起沒帶這個的客戶端（例如 0.14.0 和更早的電腦版）加不進專家模式的房間，會回 `expertNotSupported`。

## 電腦等級

練習牌局與修業模式的一般對戰可以替右家、對家、左家各選一個等級，預設都是一般；挑戰關卡的等級是固定的。榮譽榜會記下這場的等級，三家不同時依右家、對家、左家的順序列出。成就「勝過職業」要三家都是職業才算。四個等級拿到的牌與規則完全一樣，差別只在看多少資訊、想多少：

| 等級 | 看什麼 | 怎麼想 |
|---|---|---|
| 初學者 | 只看自己手牌 | 打看起來連不起來的牌，能吃就吃、能碰就碰 |
| 一般 | 只看自己的牌 | 算還差幾步聽牌，吃碰會想有沒有變快；不數張數、不防守 |
| 業餘 | 加上全桌打出與亮出的牌 | 快聽牌時用真正剩下的張數算進張；有人快聽時挑現物與筋，差太遠就保命 |
| 職業 | 加上打牌順序、花色傾向、籌碼規則與各家籌碼 | 估各家聽牌機率與放槍風險、估這手值幾台，用期望金額決定攻或守；最後一圈明顯領先就守、明顯落後就拚，籌碼快輸光就保命 |

每家電腦開局時隨機一種個性，滑鼠停在牌桌右側的名字上可以看。個性和等級無關，是同樣的局面偏向哪邊，存檔接回後不會變：

| 個性 | 怎麼打 |
|---|---|
| 穩健 | 照該等級原本的算法 |
| 愛衝 | 比較敢攻，晚一點才防守或棄胡 |
| 保守 | 比較早防守，不輕易吃牌 |
| 愛做大牌 | 為了一色、刻子與門清願意慢一點，不輕易吃牌 |

初學者憑感覺打，沒有個性之分。`Tournament` 與電腦代打都用穩健。

**不作弊**：策略只拿得到 `TableView`，裡面只有該座位合法看得到的資訊，別家手牌、別家暗槓與牌牆順序在結構上就讀不到。`BotTest` 會在實際牌局中調換別家的暗牌，確認每個等級的決定都不受影響。

職業等級用到的統計表（`OpponentRead`、`ProStrategy` 裡的常數）是離線用大量自我對戰統計出來的，對局時只查表。個性與籌碼局勢的比重在 `Posture`。

各等級的對戰成績可以這樣看，引數是每組局數：

```
java -cp build\classes;build\test-classes ezmj.Tournament 4000
```

打包時 `LICENSE` 會放進 jar 的 `META-INF\LICENSE`，以及可攜版與安裝程式的 `LICENSE.txt`。
